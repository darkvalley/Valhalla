# Valhalla Batch Text v1.6.3 — Daily Logging and Persistent Port Labels

Stable production release for ComfyUI. Based on the approved v1.6.0 code and locally tested v1.6.3 update.

## Changes since v1.6.0

### Daily workflow logs
- One UTF-8 log file **per saved workflow per calendar day**: `<workflow_name>_YYYYMMDD.txt`.
- Subsequent executions on the same day append to the existing file. A new day's first execution creates a new file.
- Every entry begins with `------------------------------------------------------------------`, followed by `ValhallaBatchText - <node title> YYYYMMDD HH:MM:SS` and the complete combined text.
- `write_log` works when `show_preview` is switched off. Both options remain opt-in.
- The selected log folder is saved in workflow properties as well as the existing widget value, so it survives saving, reopening and frontend upgrades.

### Automatic and manual input labels
- When you connect a node output such as `scene_text` to a `TEXT:n` input, Batch Text displays `scene_text`.
- Renaming a port through **Rename Slot** creates a manual display label, which takes precedence and survives saving/reloading, new connections and reordering.
- Rename the input back to its canonical `TEXT:n` name to resume automatic labeling.
- The underlying port IDs, the `TEXT_LIST` socket, native ComfyUI list behavior and join order are unchanged. Existing workflows remain compatible.

## Installation
1. Shut down ComfyUI and back up any existing `custom_nodes/Valhalla_BatchText` folder.
2. Extract `Valhalla_BatchText_v1.6.3.zip` into `custom_nodes` so that `custom_nodes/Valhalla_BatchText/__init__.py` exists.
3. Restart ComfyUI and hard-refresh the browser (`Ctrl+F5`).
4. If an earlier broken upgrade discarded the chosen log folder completely, select it again and **save the workflow**.

**Scope:** This release contains **only Valhalla Batch Text**. It does not install or update the separate `ValhallaTextStudio` custom node. Logs generated by that separate Text Inspector are not governed by this release.

Older log files are left untouched. No extra dependencies are required.
